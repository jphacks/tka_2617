# yomiyasu：読みやすい日本語

チームの3人とAIが、同じ文章を何度も読む。1回で意味が取れる文にする。

## 変えないもの

- 意味・事実・決めたこと。数値、コード、コマンド、パス、URL、issue番号、固有名詞
- ADRの決定・理由・日付。ADRは決めた当時の記録なので、言い回しだけを直す
- 引用、ライセンスの文、生成されたファイル（`docs/design_handoff_app_shell/`など）
- 情報の量。書いていないことを足さず、書いてあることを消さない。同じことの繰り返しだけはまとめてよい

古そうな内容、事実か分からない内容を見つけたら、直さずにPR本文に書き、書いた人に聞く。

## 書き方

1. 1文に1つのこと。「〜し、〜し、〜」と続く文や、読点が4つを超える文は分ける
2. 結論を先に書く。節の最初の文で、何の話かが分かるようにする
3. 主語・目的語を省きすぎない。「これ」「それ」「上記」が何を指すかを、近くに書く
4. 漢語の名詞をつなげず、動詞で書く

   | 前                     | 後                       |
   | ---------------------- | ------------------------ |
   | 未配置のPC             | 重みをまだ置いていないPC |
   | 縮尺を算出する         | 縮尺を計算する           |
   | 別途検証が必要         | あとで確かめる必要がある |
   | 〜を行う、〜を実施する | 〜する                   |
   | 〜することが可能       | 〜できる                 |
   | 〜において、〜に関して | 〜で、〜について         |

5. 同じものは同じ言葉で呼ぶ。初めて出る専門用語は、短く説明する
6. 箇条書きは、項目の形をそろえる（全部を名詞で終えるか、全部を文にする）
7. 否定を重ねない。「〜と思われる」などのぼかしは、根拠があるときだけ使う
8. 太字は、読み飛ばされると困る1か所だけに使う

## 表記

- 英語と日本語の間に半角スペースを入れない。コード・コマンド・URLの中の空白はそのまま（textlintで確かめる）
- 括弧とコロンは全角（「（）」「：」）。数字と単位は続ける（25°C、400行）
- docsは「〜する」で書き、ファイルの中でそろえる。PR本文・issueも同じ
- 見出しは日本語にする。コードや固有名詞はそのまま

## 直すときの手順

1. ファイルを全部読む。見出しを変えるなら、その見出しへのリンクを`git grep`で探し、一緒に直す
2. 直す。PRは400行くらいまでなので、フォルダや持ち主ごとに分ける
3. `pnpm lint:md`と`pnpm format`で確かめる
4. 差分を読み直し、意味・数値・リンクが変わっていないかを確かめる

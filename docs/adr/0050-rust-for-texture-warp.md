# テクスチャの三角形の貼り付けは、Rust拡張で並列に計算する

日付：2026-10-18

## 背景

テクスチャを作るときは、テンプレートの三角形（1面500〜900個）ごとに、2048×2048のテクスチャのどの画素が写真のどこを読むかを計算する。これをPythonで三角形ごとにループし、三角形を囲む範囲の格子をnumpyで作っていたため、1面約0.6秒かかっていた。

推論と切り抜きを使い回し（[ADR 0048](0048-reuse-cutout-for-texture.md)）、モデルをOpenVINOで動かす（[ADR 0049](0049-openvino-for-models.md)）と、残る時間の中ではこの計算が大きい。モデルと違い、この計算はPythonのループそのものが遅いので、速い言語に移すと効く。

## 決定

`apps/inference/native/`に、PyO3とrayonで書いたRust拡張`pitari_fast`を置く。`warp_maps`は、各テクスチャの行にかかる三角形を並び順のまま持ち、行ごとに並列に、画素が三角形の内側かを調べて読む位置を書く。三角形の内側の判定は、Python版と同じ式と順序で計算する。

`photo_to_texture.py`は、`pitari_fast`を読み込めればそれを使い、読み込めなければ同じ結果を返すPython版の`warp_maps`を使う。写真から色を読む`cv2.remap`、色の補完、GrabCutはOpenCVのまま使う。

## 理由

実写のTシャツと長そでで、Rust版とPython版の`texture.png`はテクセル単位で同じだった。貼り付けは1面約0.6秒から約0.2秒になった。残りの0.2秒の大半は、OpenCVの`remap`・`erode`と、三角形を並べるPythonの処理。

テクセルは、先に並んだ三角形が取る。行の中では三角形の順に処理し、行どうしは互いに書く場所が重ならないので、並列にしても結果が変わらない。拡張がないPCやCIでもPython版で動くので、Rustを入れていない人の作業を止めない。

## 代替案

- numpyだけで、三角形の番号の画像を作ってからまとめて計算する：Pythonのループは消えるが、三角形の番号を描く処理を別に持ち、境界の画素の扱いをPython版と合わせ直す必要がある。
- C++とpybind11で書く：速さは同じくらい。Rustのほうが、並列化（rayon）とPythonとの受け渡し（numpy crate）を安全に書け、cargoとmaturinでビルドが1つのコマンドで済む。
- 推論サービス全体をRustで書き直す：時間の大半はモデルの計算で、言語を替えても速くならない。Grounding DINOの前処理・後処理とGrabCutを移す手間に見合わない。

## 影響

速くしたいPCでは、RustとVisual StudioのC++ビルドツールを入れ、`maturin develop --release`でビルドする（推論サービスのREADME）。テクスチャ1件の中では約1秒の短縮で、推論を使い回す・OpenVINOにする変更よりずっと小さい。Python版の`warp_maps`を変えるときは、Rust版も同じに直し、`tests/test_warp_maps.py`で一致を確かめる。

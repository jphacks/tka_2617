# テクスチャを作るときは、DBに保存した表の点とA4の四隅を推論より優先する

日付：2026-10-18

## 背景

採寸画面で確かめた点とA4の四隅は、measurement画像の行の`points`・`paper_corners`に保存している。テクスチャの作業は、同じ写真の切り抜きの記録（[ADR 0048](0048-reuse-cutout-for-texture.md)）があれば使うが、無いときは写真から紙と点を推論し直していた。記録は推論サービスのPCにしか無いので、別のPC・記録を消したあと・前からある服では、画面で直したA4の誤検出をテクスチャで繰り返していた（#82）。

## 決定

apiは、表の写真と一緒に、DBの画像の大きさ・点・A4の四隅を`POST /textures`の`frontSaved`として送る。点も四隅も無い服では送らない。推論サービスは、写真の大きさが一致すれば、送られた点と四隅を切り抜きの記録や推論より優先して使う。四隅があれば紙の検出はしない。点は番号ごとに、保存した座標で記録や推論の点を置き換える。保存した点が一部の番号だけでも、テンプレートに要る点が欠けないよう、ランドマークの推論は残す。大きさが違えば使わず、今までどおり推論して、そのことを`report.json`に書く。

## 理由

DBの値は、利用者が画面で確かめて保存した最後の値なので、推論し直した値で上書きしない方がよい。すでにDBにある列だけを使うので、migrationは要らない。

## 代替案

- 服の範囲（bbox）と服の領域もDBに保存する：画面の登録の処理・migration・型が増える。範囲の検出は残るが、四隅と点が保存した値になれば、同じ誤検出は繰り返さない。
- 切り抜きの記録だけに頼る（ADR 0048のまま）：記録が無いときに、画面での修正が生かされない。

## 影響

記録が無いときも、紙の検出は省く。服の検出（範囲）・ランドマーク・GrabCutは残るので、時間はあまり変わらない。裏面はDBに点も四隅も持たないので、今までどおり。

# 完成したテクスチャは、apiが推論サービスから受け取ってStorageに置き、画像のAPIで配る

日付：2026-10-17

## 背景

[ADR 0023](0023-garment-texture-on-pc.md)では、テクスチャをPC内のフォルダにだけ作り、DB・Storage・APIには出さないと決めた。アバターに服の写真の柄を貼るには、アプリからテクスチャを取れる必要がある。推論サービスはPCで動き、DBとStorageに触れるのはapiだけ（AGENTS.md）。

## 決定

アプリが`GET /v1/garments/:id/texture`で状態を聞くと、apiが推論サービスの`GET /textures/{garmentId}`に問い合わせる。完成していれば、`GET /textures/{garmentId}/{job}/texture.png`で画像を受け取る。Storageの`garments`バケットに置き、`garment_images`のrole`texture`として記録する。画像は、服の写真と同じ`GET /v1/garments/:id/images/:imageId`で配る。服の一覧と詳細の`images`には入れず、画像のIDは`GET /v1/garments/:id/texture`だけで返す。

作成中・失敗の状態は推論サービスだけが持ち、DBには完成したテクスチャだけを記録する。どの作業から作ったか（作業フォルダ名）を`texture_job`に持ち、同じ作業を2回保存しない。差し替えはDBの関数`save_garment_texture`で1つのトランザクションにする。関数は服の行をロックしたまま、作業のもとになった裏面が今の裏面かを確かめ直し、違えば保存しない。apiが状態を確かめてから保存するまでの間に、裏面が撮り直されることがあるため。

裏面を撮り直す前の写真から作ったテクスチャは使わない。apiは依頼のときに裏面の画像のID（`backImageId`）を推論サービスへ送り、推論サービスはそれを作業に記録して、状態と一緒に返す。今の裏面と違う作業は、無い扱いにする。保存済みのテクスチャも、裏面の行より前に保存したものは使わない。新しいテクスチャができるまで、古い行は残る。状態のAPIで古いかどうかを確かめ、このAPIだけが画像のIDを渡す。

作り直しの間や、作り直しに失敗したときも、今の写真から前に作ったテクスチャがあれば、`processing`や`failed`と一緒にそのIDを返す。推論サービスにつながらないときは、保存済みのテクスチャがあれば返す。失敗の理由は画面に出さず、apiのログに残す。

## 理由

apiが聞きに行く形なら、推論サービスはapiのURLやトークンを持たなくてよく、apiが止まっていた間に完成したものも後で受け取れる。状態をDBにも持つと、推論サービスと食い違ったときにどちらが正しいか分からなくなる。

テクスチャは、すでに`/api/garments/:id/images/:imageId`で配っている服の写真から作る。公開の`/api/*`から新しく取られる情報は無い（[ADR 0002](0002-no-login-yet.md)）。

保存済みのテクスチャが裏面より古いかは、テクスチャの行と裏面の行の`created_at`で比べる。どちらもDBが付けるので、推論サービスのPCと時計がずれていても比べられる。

作り直しの間も前のテクスチャを返すことと、依頼のときにどの写真からかを送ることは、runaの案（#67、#71）から取り入れた。作り直しの間に柄が消えず、撮り直した直後に古い写真の作業が完成しても取り違えない。

## 代替案

- 推論サービスがSupabaseに直接置く：推論サービスにsecret keyが要り、DBとStorageに触れるのはapiだけという境界が崩れる。
- 推論サービスが完成時にapiへ送る：送れなかったときに結果を失う。
- 推論サービスから画像を直接配る：スマホから推論サービスに届かせる必要があり、トークンを画面に出せない。
- テクスチャ用のテーブル（`garment_textures`）に、依頼ごとの状態と依頼IDを持つ（runaの最初の案）：作成中の依頼がDBに残るので、推論サービスの再起動や時間切れを、apiが別に失敗へ変える必要がある。服の削除と画像の取得も別に作る必要がある。`garment_images`のroleにすれば、今の処理がそのまま使える。

## 影響

推論サービスに状態のAPIが入るまでは、推論サービスが404を返すので、状態は常に「まだ作っていない」になる。

推論サービスが`backImageId`を返すまでは、裏面を差し替えた直後に、古い写真の作業の完成から新しい作業の開始までの間に聞かれると、古い写真のテクスチャを保存することがある。新しい作業が完成すれば差し替わる。

最初は2048pxのPNGが8MiBを超えると見積もり、Storageの1ファイルの上限を16MiBに上げた。実際のテクスチャは1枚約0.5MB（#67のrunaの計測）なので、上限は余裕として残す。利用者が上げる写真は、apiが別に8MiBまでに抑える。

テクスチャを作るテンプレートのUVは、Tシャツ・長そで・ズボンの3つとも、アプリのglbと一致することをrunaが数値で確かめた（#67、[ADR 0037](0037-app-glb-uv-is-source.md)）。アプリで実際に貼って確かめるのは#67の残り。

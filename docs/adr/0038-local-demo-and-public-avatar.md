# 0038 当日のデモはPCで全サービスを動かし、Vercelは見本アバターの体験用にする

日付：2026-10-17

## 背景

Vercelにはwebだけを公開している。api・Supabase・CPUの推論はローカルで動くため、本番のクローゼットから服を登録する流れは使えない。見本の服を使うアバターは、これらへ接続せず体験できる。

[#66](https://github.com/jphacks/tka_2617/issues/66)で、当日のPCと通信の予備は決まっていたが、Vercelの役割が残っていた。提出で見せるものと会場の実演を分けて決める。

## 決定

- 当日の実演はrunaのWindowsのPCで行う。web・api・ローカルSupabase・推論を同じPCで動かす。推論モデルとUVテンプレートがそろっているため。使えなければnakamuのPCへ切り替え、同じ準備と確認を行う
- スマホはPCと同じネットワークにつなぎ、PCのwebのURLを開く。会場のWi-Fiで端末間の通信ができなければ、スマホのテザリングへ切り替える。インターネットへのポート公開はしない
- デモではwebを事前にbuildし、`next start --hostname 0.0.0.0`で起動する。開発サーバーの`allowedDevOrigins`の制限を当日の動作条件に持ち込まない。起動済みのSupabaseにも、新しいmigrationは`supabase migration up --local`で適用する
- 実演は「撮影して登録→登録した服をアバターに着せる→寸法を変える→上下の服の組み合わせを変える」の順にする。写真のテクスチャが間に合わなくても、無地の服でこの流れを通す
- Vercelは[見本アバターの体験](https://pitari-taupe.vercel.app/avatar)とPWAの確認に使う。READMEからは`/avatar`へ直接案内し、撮影・採寸・クローゼットへの保存にはローカル環境が必要と明記する
- [#78](https://github.com/jphacks/tka_2617/issues/78)で撮影する提出用のデモ動画を、会場の予備にも使う。会場でネットワークが使えなくても再生できるよう、事前にPCへ保存する

## 理由

- モデルと型紙があるPCを使えば、クラウドへの移設や追加の契約をせず実演できる
- 公開体験と実演の範囲を説明し、公開URLから保存もできると誤解されないようにする
- apiをインターネットへ公開しないので、ログインが無い状態で誰でも登録・削除できる範囲を広げない（[ADR 0002](0002-no-login-yet.md)）
- 提出用と予備の動画を兼ねれば、同じ流れを撮り直す必要が無い

## 代替案

- api・Supabase・推論もクラウドへ移す：環境と公開範囲の設定が増え、手元にあるCPUモデルと型紙の準備をやり直す必要がある。デモまでは行わない
- Vercelのトップページを全機能の体験用として案内する：apiへ接続できず、クローゼットの読み込みエラーから始まるため採らない
- 当日は動画だけで見せる：通信やPCの問題に強いが、現物を撮って登録する流れを実演できないため、予備にする

## 影響

- [ADR 0004](0004-deploy-web-with-vercel-cli.md)で未決だったapi・Supabaseの当日の置き場所を、この決定で補う
- [#76](https://github.com/jphacks/tka_2617/issues/76)で、起動・migration・スマホ接続・予備への切り替えを手順書にし、runaのPCと実機で通し練習する。このADRは実機で動作確認済みという記録ではない
- 同じWi-Fiでもテザリングでも、PCとデモのスマホが通信できることを事前に確かめる。ネット接続があるだけでは端末間の通信を保証しない
- 当日のLAN接続はHTTPでよく、PWAとしてのインストール確認は公開版のHTTPSで行う（[ADR 0003](0003-pwa.md)）
- 公開版とローカル版は別の環境なので、服のデータを共有しない。アバター設定もブラウザの保存先がURLごとに分かれる

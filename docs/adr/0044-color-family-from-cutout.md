# 0044 服の色の系統は、ブラウザで切り抜きの画素ごとに分け、いちばん多い系統にする

日付：2026-10-18

## 背景

服を足したときに、同じ系統の服が何着あるかを知らせたい（#112）。似た服を買いすぎないよう、その場で気づけるようにするため。系統は、上に着るもの・下に着るものと、色で比べる。服には色の情報が無かった。

ZOZOの商品の色名から決める案もあったが、利用規約で商品ページを自動で読めないと分かり（#111）、使えなくなった。

## 決定

- 服に色の系統を1つ持たせる（`garments.color_family`）。系統は白・黒・グレー・紺・ベージュ・茶・赤・ピンク・オレンジ・黄・緑・青・紫の13個。
- 撮影で登録するとき、ブラウザで切り抜きのPNGを64pxまで縮め、透けていない画素（アルファ128以上）ごとに系統を決め、いちばん多い系統にする。登録と一緒に`metadata.colorFamily`で送る。
- 1つの画素の分け方（`apps/web/src/lib/color-family.ts`）。明るさは`max(r,g,b)/255`、彩度は`(max-min)/max`、色みは`(max-min)/255`。
  - 明るさが0.15未満は黒。
  - 彩度が0.2未満か、色みが0.08未満は、明るさだけで分ける。0.75以上は白、0.3未満は黒、その間はグレー。
  - それ以外は色相で分ける。
    - 15°未満と345°以上は赤（淡くて明るければピンク）。
    - 15〜45°は、暗ければ茶、淡ければベージュ、濃ければオレンジ。
    - 45〜70°は、暗ければ緑（カーキ・オリーブ）、淡ければベージュ、濃ければ黄。
    - 70〜170°は緑。
    - 170〜250°は、明るさが0.5未満なら紺、それ以上は青。
    - 250〜290°は紫。
    - 290〜345°は、明るければピンク、暗ければ紫。
- 色を決められなかったとき（透けていない画素が無い、画像を読めない）は、登録を止めずにnullで保存する。前からある服もnull。
- 同じ系統は、上下（トップス＝Tシャツ・長そで・シャツ、ボトムス＝ズボン）と色の系統が両方同じ服。色がnullの服は、どの色とも同じにしない。足した服の色がnullなら、上下だけで比べる。
- 登録のあとに下から出すポップに、同じ系統の服の数と写真を出す。自動で決めた色が違えば、ポップの中で選び直せる（PATCH）。

## 理由

- 平均の色にせず多数決にするのは、柄やしわの影で平均の色がにごるため。紺のTシャツの影がほぼ黒になっても、紺の画素のほうが多ければ紺になる。
- 白と黒を、色相より先に彩度と明るさで分けるのは、部屋の光で白い服が黄みがかって写るため。彩度が低ければ、色相を見ずに白にする。
- 暗い紺を黒にしないよう、明るさだけで黒にするしきい値を0.15と低めにした。それより明るければ、色みが0.08以上ある暗い青は紺になる。
- 切り抜きは、推論サービスが服の範囲だけを残したPNGで、ブラウザが登録の前から持っている。ブラウザで決めれば、推論サービス（Python）にもapiにも、PNGを読む処理を足さずに済む。
- 13個は、#113のコーデの提案で「何とでも合う色」（白・黒・グレー・紺・ベージュ）を見分けられ、似た服を数えるときに細かすぎない数にした。

## 代替案

- apiで切り抜きのPNGを読んで決める：Node.jsにはPNGを画素まで読む機能が無く、自前で書くか依存を足す必要がある。ブラウザはcanvasで読める。
- 推論サービスで決める：服の範囲のマスクと元の写真を持っているが、推論サービスの応答の形を変えることになり、担当をまたぐ。
- 利用者に色を選んでもらう：登録の手間が増える。自動で決めて、違うときだけ直してもらう形にした。
- 色の名前を細かく持つ（ネイビー・インディゴなど）：同じ系統をまとめて数えたいので、系統だけにした。

## 影響

- 前からある服は色がnullなので、同じ系統の服として数えない。色を付けたいときは、PATCHで送る。
- 同じ系統の服は、webが持つ服の一覧（`GET /v1/garments`の新しい100着）から数える。クローゼットの画面と同じく、100着を超えると古い服を数え漏れる。服が増えたら、apiで数える形に変える。
- 写真の光によっては、白がベージュ、紺が黒になるなど、違う系統になることがある。ポップで直せる。
- A4の白い紙の色でホワイトバランスをそろえると、光の影響を減らせる。必要になったら足す。
- #113のコーデの提案は、`colorFamily`で色の組み合わせを選べる。

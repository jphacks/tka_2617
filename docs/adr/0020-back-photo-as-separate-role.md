# 服の裏面の写真を別のroleで保存し、詳細画面で表と並べる

日付：2026-10-17

## 背景

服の裏側の柄やプリントを確認したい。今は表の写真1枚だけを保存していて、クローゼットにも表だけが出る。

## 決定

裏面の写真は`garment_images`の新しいrole`back`（JPEG）と`back_cutout`（表示用の透過PNG）で保存する。登録・差し替えは`PUT /v1/garments/:id/back`で、表の登録とは分ける。撮影画面では表の採寸後、登録前に任意で裏面を撮り、表の登録が済んでから裏面を送る。登録済みの服には詳細画面から裏面を足せる。

裏面は採寸しない。表と同じくA4→服の範囲→切り抜きの順に既存の推論APIを呼び、ランドマークは求めない。範囲が見つからなければJPEGだけを保存し、そのまま表示する。

クローゼットの一覧は表の画像だけを表示する。一覧の服をタップすると`/garments/[id]`の詳細画面を開き、表と裏を左右に並べる。

## 理由

roleを分ければ、既存の「服1着につき各role1枚」の制約と画像取得の経路をそのまま使える。裏面の登録を別のAPIにすると、登録済みの服にも後から裏面を足せ、表の登録処理を複雑にしない。推論サービスは変更せずに済む。

詳細を別の画面にすると、スマホの戻る操作で一覧へ戻れ、URLで服を指せる。

## 代替案

- 裏面を別の服として登録する：表と裏の対応を別に持つ必要があり、一覧に裏面が混ざる。
- 表の登録APIで裏面も受け取る：後から裏面を足すAPIが別に必要になり、同じ処理が2か所にできる。
- 一覧の中で項目を開いて表示する：一覧の並びが崩れ、戻る操作で閉じられない。

## 影響

DBのroleの制約を変えた。表の登録と裏面の登録は別のリクエストなので、裏面だけ失敗した場合は表を残し、詳細画面から撮り直してもらう。差し替えのたびに新しいキーで保存し、古い裏面の画像は保存後に消す。UVテクスチャ（[ADR 0015](0015-uv-template-for-photo-texture.md)）にはまだ裏面を使わない。

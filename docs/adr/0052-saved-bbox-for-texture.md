# 採寸画面で確かめた服の範囲もDBに保存し、テクスチャを作るときに服の検出を省く

日付：2026-10-18

## 背景

[ADR 0051](0051-saved-points-for-texture.md)で、テクスチャを作るときは、DBに保存した表の点とA4の四隅を推論より優先するようにした。服の範囲（bbox）はDBに無いので、代替案として見送った。そのため、切り抜きの記録（[ADR 0048](0048-reuse-cutout-for-texture.md)）が無い服では、テクスチャの作業で服の検出（Grounding DINO）をやり直していた。服の検出は1枚約24秒（OpenVINOで約6秒）かかり、採寸画面で直した範囲とは違う範囲を見つけることもある（#82）。

## 決定

measurement画像の行に`bbox`（jsonb、画像の座標の`[x1, y1, x2, y2]`）を足す。webは登録のときに、採寸画面で確かめた範囲をmetadataの`bbox`で送り、apiはmeasurement画像の行に保存する。範囲が写真の端をはみ出していたら写真の中に切り詰め、写真の外にあれば保存しない。登録は止めない。前からある写真とmeasurement以外の写真は`null`にする。

apiは、テクスチャの依頼の`frontSaved`に`bbox`も入れる。推論サービスは、写真と大きさが同じで、切り抜きの記録が無いときは、保存した範囲を服の検出の代わりに使う。ランドマークの推論と切り抜きは、その範囲で行う。切り抜きの記録があるときは、範囲から作った服の領域ごと記録を使う。

## 理由

採寸画面で確かめた範囲は、利用者が見て直した最後の値なので、推論し直した値で置き換えない方がよい。ADR 0051の点と四隅と合わせれば、記録が無い服でも、採寸画面の結果をそのまま使える。服の検出を省けるので、記録が無い服のテクスチャが1面あたり約6〜24秒速くなる。

範囲は推論の結果を画面で動かしたもので、浮動小数の誤差で写真の端を少しはみ出すことがある。範囲は補助の情報なので、そのせいで服の登録を失敗させず、切り詰めて保存する。

## 代替案

- 服の領域（マスク）もDBかStorageに保存する：GrabCutも省けるが、画像が1枚増え、Storageと削除の処理も増える。範囲があれば、同じ写真から同じ領域をほぼ作れる。
- 範囲を保存しない（ADR 0051のまま）：記録が無い服で、服の検出の時間と誤検出が残る。

## 影響

新しく登録した服は、記録が無いPCでも、テクスチャの作業で服の検出を省く。前からある服は`bbox`が`null`なので、今までどおり検出する。裏面は範囲を保存しないので、今までどおり。

# テクスチャの保存フォルダを生成日時から始める

日付：2026-10-17

## 背景

`textures/{服ID}/{日時}/`では、服IDのフォルダを全部開かないと最新の結果が分からない。固定名のtexture.pngだけでは、画像を受け渡したときに対象の服や生成時期も分からない。

## 決定

作業フォルダは`textures/{YYYY-MM-DD_HH-mm-ss}_{種類}_{服ID先頭8文字}/`の1階層にし、完成画像にはフォルダと同じ名前の`.png`も置く。生成日時は処理開始時刻のJSTで、先頭に置くので名前順が生成順になる。同じ服の同じ秒の再生成は、末尾に`_2`などを付けて分ける。

登録日時は名前に入れず、apiがDBのcreated_atを取得して推論へ渡し、job.jsonのgarmentCreatedAtに保存する。名前を短くし、日時が1つだけになるようにするため。job.jsonにはcreatedAt・completedAtとtextureFileも保存する。登録日時が得られないものはnullとし、生成日時で代用しない。失敗した処理には完成画像の名前を記録しない。

## 影響

既存のBlender確認スクリプト用にtexture.pngも保持する。確認用画像は同じバイト列のコピーで、既存ファイルを置き換えない。保存先は引き続きPC内だけで、取得API・DBの構造・公開範囲は変えない。

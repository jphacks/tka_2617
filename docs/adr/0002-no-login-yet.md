# 0002 ログインはまだ作らず、デモ用の1ユーザーで進める

日付：2026-10-05

## 背景

ハッカソンの期間で、まず服の撮影・保存・着せ替えを動かしたい。ログインは必ず作るが、今は手を広げすぎない。

## 決定

- 全員を`DEMO_PROFILE_ID`の1ユーザーとして扱う
- `profile_id`はリクエストから受け取らず、apiが決める

## 理由

- ログインが無くても、作りたい機能の確認には困らない
- `profile_id`をapiだけが決める形にしておけば、ログインを入れたときに差し替える場所が1か所で済む

## 既知のリスク

- URLを知っていれば、誰でも`/api/*`を呼べる。服の登録や削除もできる
- DBのキーはapiにしか無いので、DBを直接触られることはない（[0001](0001-separate-web-and-api.md)）

ログインを入れるまでは、次を守る。

- デモが終わったら止める
- 個人を特定できる情報を返すAPIを足さない

## 代替案

- 最初からSupabase Authを入れる：安全だが、ハッカソンの序盤にやることが増える

## 影響

- Supabase Authを入れ、apiが`profile_id`をトークンから決めるようになったら、このADRを「置き換え済み」にする。そのときに、AGENTS.mdの「既知のリスク」を消す

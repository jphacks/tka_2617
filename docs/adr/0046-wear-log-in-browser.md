# 0046 着た服の記録は、ログインを入れるまでブラウザのlocalStorageに保存する

日付：2026-10-18

## 背景

記録の画面（#108で置き場所だけ作った`/log`）に、日ごとに着た服を残すカレンダーを作る（#114）。保存先を決めていなかった。

## 決定

- 記録は、日付（`YYYY-MM-DD`、端末の時刻）ごとに、上の服と下の服のID（`{ top, bottom }`）を持つ。片方だけでもよい
- ブラウザのlocalStorage（`pitari.wear-log`）に保存する。読み書きは`apps/web/src/lib/wear-log.ts`にまとめる
- 記録の画面では、日を選んで、クローゼットの上と下から1着ずつ選んで残す。まだ来ていない日には残せない
- 今日のコーデの提案（#113）の「これを着る」からも、同じ`lib/wear-log.ts`の`record`で残す

## 理由

- DBに保存すると、全員が同じデモユーザーなので記録が混ざる。さらに、いつ何を着たかという暮らしの情報を、誰でも呼べる`/api/*`から返すことになる（[ADR 0002](0002-no-login-yet.md)）。アバターの設定（[ADR 0036](0036-avatar-settings-in-browser.md)）と同じ理由
- 服の名前や写真は持たず、服のIDだけを持つ。名前や写真を変えても、記録の表示が古くならない

## 代替案

- DBに`wear_logs`のテーブルを作る：別の端末でも見られるが、上のとおり、ログインが無いうちは混ざり、漏れる
- 服の名前も一緒に保存する：服を消しても名前が残るが、変えた名前が記録に反映されない

## 影響

- 記録は端末とブラウザごとに分かれる。画面に「この端末のブラウザに残る」と出す。サイトのデータを消すと、記録も消える
- クローゼットから消した服は、記録に「クローゼットから消した服」と出す
- 保存した値が壊れていたら、記録の無い状態から始める。localStorageを使えないブラウザでは、画面を開いている間だけ残る
- ログインを入れたら、DBに移す。そのときは、localStorageの記録を初回だけ送って移す

# 推論サービスのテクスチャの作業は服ごとに新しい3件まで残し、服を消したら片付ける

日付：2026-10-18

## 背景

推論サービスは、テクスチャの作業ごとに`apps/inference/textures/`へフォルダを作り、受け取った表と裏の写真・テクスチャ・確認用の画像を書き出す。切り抜きの記録（[ADR 0048](0048-reuse-cutout-for-texture.md)）にも、写真のハッシュで服の範囲・点・服の領域を残す。

服を消しても、apiはDBとStorageだけを消していた。待っている作業は取り消せず、作り直すたびにフォルダが増え、服を消したあとも写真がPCに残り続けた（#86）。READMEは、確かめるためにローカルの結果を残すと書いていたが、いつまで残すかは決めていなかった。

## 決定

- 服が残っている間は、作業フォルダを服ごとに新しいものから3件まで残す。作業が終わるたびに、古いものを消す。失敗した作業も1件に数える。
- apiは服を消すとき、DBとStorageを消したあとに、推論サービスへ`DELETE /textures/{服ID}`を送る。`POST /textures`と同じBearerトークンを付ける。
- 推論サービスは、`DELETE /textures/{服ID}`を受けたら、次のように片付ける。
  - 待っている作業は取り消す。
  - 作っている最中の作業は止めない。書きかけのフォルダを消さず、作業が終わってから消す。
  - その服の作業フォルダ（入力の写真・テクスチャ・確認用の画像・失敗した作業）をすべて消す。
  - フォルダの中の写真の切り抜きの記録も消す。
- 推論サービスにつながらなくても、apiは服の削除を済ませて204を返し、ログに残す。

## 理由

DBとStorageが正なので、推論サービスの片付けに失敗しても、服は消えたとして扱う。服の行が無ければ、apiは推論サービスの結果を取りに行かず、Storageにも保存しない。なので、消したあとに作業が終わっても、テクスチャはアプリに戻らない。

作業中のスレッドは途中で止められず、フォルダを先に消すと書き込みが失敗する。そこで、終わるのを待ってから消す。

3件残すのは、作り直す前後で仕上がりを比べたり、`benchmark.py`で1件を作り直したりするため。最新の1件はapiが使い、前の2件は確かめるために使う。

## 代替案

- 服を消しても推論サービスには知らせず、期限で消す：服が消えたかを推論サービスは知らないので、写真が期限まで残る。
- apiが推論サービスの片付けの失敗で削除を止める：推論サービスを止めているPCでは、服を消せなくなる。

## 影響

推論サービスが止まっている間に消した服のフォルダは残る。フォルダ名の最後に服IDの先頭8文字があるので、手で消せる。切り抜きの記録は、今までどおり新しいものから200件まで残る。

# 服の検出とランドマークは、OpenVINOに変換したモデルをCPUで動かす

日付：2026-10-18

## 背景

採寸では、服の検出（Grounding DINO）にCPUの4スレッドで1枚約23秒、ランドマーク（HRNet）に約1.8秒かかる。採寸の画面は、表の写真で約25秒、裏面の登録でも同じだけ待たせていた。テクスチャを作るときに同じ写真の結果を使い回せない場合（[ADR 0042](0042-reuse-cutout-for-texture.md)）も、2枚分かかる。

モデルはPyTorchの中ですでにC++で動いているため、呼ぶ側をRustやC++に書き換えても速くならない。速くするには、モデルを動かす仕組みを変える必要がある。開発に使うPCはIntelのCPU（i7-1255U）と内蔵GPU（Iris Xe）を持つ（[ADR 0010](0010-local-garment-measurement.md)）。

## 決定

`prepare_models.py --openvino`で、HRNetとGrounding DINOをOpenVINOのIRに変換して`models/openvino/`に置く。推論サービスは、IRがあればOpenVINOのCPUで動かし、なければ今までどおりPyTorchで動かす。

変換したDINOは、変換に使った画像の大きさでしか動かない。縦長（1066×800）と横長（800×1066）の2つを作り、写真をその大きさに収めて余白を足す。余白は`pixel_mask`で隠す。文は16トークンまで埋める。変換を通すため、transformersの関数のうち、変換できない`logit`と、文の区切りをPythonのループで数える処理を、同じ結果の式に置き換えてから変換する。

## 理由

このPCで静かなときに測ると、服の検出は1枚約23秒から約6秒、ランドマークは約1.8秒から約0.9秒になった。実写の5着（Tシャツ・長そで・シャツ・パンツ）で、90度回した写真・縮めた写真・種類を自動で選ぶ文も含めた20通りのうち、最も点数の高い枠はどれもPyTorchとIoU 0.998以上で一致した。ランドマークは16面すべてで同じ位置だった。

PyTorchのスレッドを4から8に増やすだけでも約2倍速くなるが、OpenVINOのほうがさらに速い。IRがなければPyTorchで動くので、変換していないPCでも今までどおり使える。

## 代替案

- 内蔵GPUで動かす：最初の試しでは約2.6秒だったが、上の置き換えをしたDINOは、精度をf16・f32のどちらにしても推論がドライバのエラー（CL_EXEC_STATUS_ERROR）で止まった。初回の準備にも数分かかる。
- 正方形（1066×1066）の1つだけにする：モデルは1つで済むが、計算が増えてCPUで約10秒になり、GPUでも動かなかった。
- ONNX Runtimeを使う：同じく変換が要り、IntelのCPUではOpenVINOのほうが速いとされる。依存を増やして比べるほどの差はない。
- 読み込みの結果をキャッシュ（`CACHE_DIR`）に残す：起動時の読み込みが57秒から45秒になるだけで、0.9GBを使う。読み込みは起動時に裏で済ませる（推論サービスの起動直後の採寸は最大60秒待つ）。

## 影響

`openvino`を依存に足す（約85MB）。`models/openvino/`に約0.8GB置き、Gitには含めない。変換には10分ほどかかり、モデルかOpenVINOを入れ替えたら、消してから変換し直す。起動時の読み込みは約1分になる。結果はPyTorchとわずかに違うことがあるが、上の比較では選ぶ枠と点は変わらなかった。`/status`の`device`は今までどおり`cpu`を返す。

# 0008 身長はBlenderで作った身長キーで変え、基準寸法とキーの効き方は身長ごとの表で持つ

日付：2026-10-12

## 背景

ユーザーには最初に身長と体型を入力してもらう。ただ、男性アバター（`avatar_male.glb`）は、MPFBのマクロ`height`0.5（172.91cm）の1つの身長でしか作っていなかった。

MPFBのマクロ`height`と身長は、0.5を境に2本の直線になっている。0.5より下は0.01あたり約1.42cm、上は約2.80cm伸びる。低い側と高い側で、別の形を混ぜているためだと考えられる。

## 決定

- 身長キーを`height_up`／`height_down`の2つにする。標準の身長172.91cmからの差で、値1.0＝1cm。高ければ`height_up`、低ければ`height_down`だけを使う
- 実測の身長差が±20cmになるマクロの値を探して体を作り、mhcloでTシャツを着せ直して、1/20倍で1cmキーにする。体とTシャツの両方に持たせる
- 入力できる身長は150〜195cmにする
- 体型・身長（150、160、172.91、185、195cm）ごとに、Tシャツの基準寸法、サイズキーの効き方M、体の身幅を測って`tshirt_male_height.json`に書き出す。ブラウザは前後の身長の値を直線で補間する
- 身長を変えても、服の実寸は変えない。身長キーで背の高さに合わせた着方にし、サイズキーで入力の実寸に戻す
- 身幅は、切り口で120°より鋭く折り返す点を除いてから測る。測り方の定義（脇の下の1cm下で胴を水平に切った一周÷2）は変えない

## 理由

- 身長に合わせて手足や胴の比率も変わり、全体を拡大縮小するより自然な体になる
- MPFBは低い側と高い側で別の形を使うので、1つのキーをマイナスに動かしても低い人の形にならない。2つに分ければ、それぞれの側で身長がマクロに比例し、範囲の中を正確に表せる
- 体型ごとに1つのMと、身長1cmあたりの基準寸法の変化で済ませると、ぽっちゃり・195cmで身幅の誤差が1.29cmになり、許容（±1cm）を超えた。体型と身長の組み合わせでMが少し変わるため、身長ごとに測る
- 身幅が跳ねたのは、ぽっちゃりの体型キーと高い側の身長キーを足した形で、脇の縫い目に外から見えない小さな折れができ、切り口がそこで行って戻っていたため。折り返しを除いても、ほかの体型・身長の値は変わらなかった

## 代替案

- アバターと服をまとめて拡大縮小する：Blenderの作業は要らないが、手足や胴の比率が変わらない
- 身長を何段階かに分ける：作業は少ないが、入力した身長がそのまま反映されない
- ぽっちゃり専用の身長キーを作る：体型と身長を足し合わせる近似をやめられるが、キーが増える。折れの原因が元の服のメッシュにあれば直らない
- 合格の基準を緩める：作業は要らないが、合意した基準を変えることになる

## 影響

- 体型キーと身長キーは足し合わせて使う近似になる。検証スクリプトは、標準と150〜195cmの8点で寸法の誤差を確かめる。最大はぽっちゃり・195cmの0.60cmで、すべて許容の中
- `tshirt_male_base.json`と`tshirt_male_correction.json`は標準の身長の分だけの表として残しているが、webは使っていない
- 身長が高いほど体が大きくなるので、3D表示のカメラは身長に合わせて動かす
- `/avatar`の`tshirt.glb`（[0006](0006-solve-shape-keys-in-browser.md)）は、別の方式（測って直すのを繰り返す）でキーの値を解いている。本番画面に組み込むときに、どちらかへ寄せる
- 生成スクリプトは、途中でPythonのエラーが出てもBlenderが終了コード0を返す。ログの`[pitari] 完了`で終わったかを見る

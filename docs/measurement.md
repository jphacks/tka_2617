# 写真からの採寸

最初の版は、推論をローカルのCPUで動かす。クラウドのGPUは契約しない。1枚に1着を平らに置き、本物のA4の紙（21cm×29.7cm）を同じ平面に置く。表と裏の写真を登録すると、PCの中でテクスチャを作る。

## 計算方法

番号は、DeepFashion2の種類ごとに1から数える。測定用の画像の座標で計算し、画像のpixelsPerCmでcmに直す。

| カテゴリ         | 項目            | 計算               |
| ---------------- | --------------- | ------------------ |
| short_sleeve_top | shoulderWidthCm | 距離(7,25)         |
| short_sleeve_top | sleeveLengthCm  | 距離(7,9)          |
| short_sleeve_top | bodyWidthCm     | 距離(12,20)        |
| short_sleeve_top | bodyLengthCm    | 距離(1,16)         |
| long_sleeve_top  | shoulderWidthCm | 距離(7,33)         |
| long_sleeve_top  | sleeveLengthCm  | 距離(7,11)         |
| long_sleeve_top  | bodyWidthCm     | 距離(16,24)        |
| long_sleeve_top  | bodyLengthCm    | 距離(1,20)         |
| trousers         | waistCm         | 距離(1,3)×2        |
| trousers         | hipCm           | 距離(4,14)×2       |
| trousers         | thighWidthCm    | 距離(9,14)         |
| trousers         | riseCm          | 距離(2,9)          |
| trousers         | inseamCm        | 距離(9,中点(7,11)) |
| trousers         | hemWidthCm      | 距離(11,12)        |

shirtは、long_sleeve_topと同じ点と計算を使う。DeepFashion2にはシャツの種類が無く、推論では長そでとして見つける。

長そでは、DeepFashion2のlong sleeve top（カテゴリ2、33点）を使う。HRNetが出す0始まりの25〜57番を、種類の中の1〜33番に戻す。寸法の項目と単位はTシャツと同じで、点番号だけが違う。[公式のランドマークの図](https://github.com/switchablenorms/DeepFashion2/blob/master/images/cls.jpg)と対応している。袖丈は肩先から袖口までの直線の距離なので、袖を伸ばし、身頃と重ならないように撮る。

股下は、利用者が決めた中点の方式で測る。ふつうの、片脚の縫い目に沿った股下とは違い、脚の開き方で変わる。ウエストとヒップは周囲長の近似値。ほかの項目は2倍しない。すべての項目が、ブランドの測り方と同じとは限らない。今のバージョンは`df2-a4-flat-midpoint-v2`。v1から、点番号の式は変えずに、遠近の補正をやめた。

## 画像と点

アップロードの前に、向きを正し、縦横の比を保ったまま、長辺1600px以下のJPEGに描き直して、EXIFを消す。そのあとは、この画像を変形しない。A4の四隅・服の範囲・ランドマークは、どれもこの画像のピクセル座標。モデルの中で切り抜いたり縮めたりした座標も、この画像の座標に戻す。表示の大きさでの座標は保存しない。

A4の向かい合う辺の長さを平均し、大きいほうを長辺、小さいほうを短辺にする。`pixelsPerCm = (長辺px / 29.7 + 短辺px / 21) / 2`。平らに置いて真上から撮ったものとして、次を確かめる。大きく外れたときは補正せず、縮尺をnullにする。

- 四隅が凸になっているか
- 四隅が画像内にあるか
- 直角からどれだけずれているか
- 向かい合う辺の長さの差
- 縦と横の縮尺の差

A4は自動で見つけて測り、結果の上で四隅をドラッグして直せる。紙ではない長方形を拾ったときは、手で直す。

見つけ方は、まず3色とも明るい白い領域から、A4の縦横比で直角に近い四角形を探す。木の机のように紙と色が近い背景や、紙に物が触れている写真では、輪郭の線が途切れたり、つながったりするため。白い画素の輪郭は紙の縁より半画素内側にあるので、各辺を半画素外へ出す。しきい値ごとに見つけた同じ紙の四隅は、平均する。白い四角形が無いときだけ、輪郭の線の四角形から探す。

点の確信度は、可視性を表すvとは別のもの。HRNetのスコアを可視性へ変換しない。信頼できない点は未設定にし、要る寸法は数字の入力で補う。

## 画面での出し方

利用者の画面には、服のランドマークの点・番号・編集の操作を出さない。中の点を使い、区間を両端の矢印と寸法の名前で示す。区間は、肩幅・袖丈・身幅・着丈か、ウエスト・ヒップ・わたり幅・股上・股下・裾幅。要る点が足りない区間には、矢印を出さない。結果は最初に「寸法」を出し、A4と服の範囲の調整点は、それぞれのモードでだけ出す。

「寸法を測定」を押すと、A4→服の種類と範囲→ランドマーク→背景の切り抜き、の順に実行する。進み具合は、各工程の始まりの位置と経過時間から目安を求め、1%刻みで出す。経過した秒数も出す。次の工程に進むまでは、その工程の境目を超えない。100%は、すべての処理が終わったときだけ出す。残り時間や、推論の中で測った割合ではない。

A4を変えたら、縮尺・寸法・切り抜きを更新する。服の範囲を変えたら、ランドマーク・寸法・切り抜きを更新する。寸法を直接入力した項目は、点を直しても上書きしない。

切り抜きには、OpenCVのGrabCutを使う。A4と範囲の外を背景として指定し、服のいちばん大きなつながった領域を、透過PNGとして保存する。ズボンでは、ランドマークの14点で囲んだ輪郭の外も背景として教え、脚の間の床を除く（[ADR 0024](adr/0024-trousers-cutout-with-landmarks.md)）。服と背景が似た色のときや、薄い部分では、失敗することがある。プレビューを確かめ、範囲を直して作り直す。切り抜きはクローゼットに出すためのもので、UVテクスチャではない。

登録するときは、画面で決めた寸法（手で直した値も含む）を、服と一緒に保存する。クローゼットと撮影の画面の一覧は、保存した寸法をcm付きで出し、値の無い項目は「未測定」と出す。

## 検証

まず、重みの取得、CPUでの推論、肩幅の計算を確かめる。最初の読み込みと、2回目からの推論の時間は分けて測る。本物のメジャーで同じ点を測り、cmの誤差・撮り直したときのばらつき・手で直した割合を記録する。ランダムな重みで出た結果を、服の推論の結果として扱わない。

### メジャーとの比べ（Tシャツ4着）

JPHACKSのTシャツ4着（S・M・L・XL）を、アプリとメジャーの両方で測った（2026-10-18、nakamu）。アプリの値は、自動で測ったまま、手で直していない。各マスは「アプリ / メジャー（差）」で、差は「アプリ − メジャー」、単位はcm。

| サイズ | 着丈                | 身幅                | 肩幅                | 袖丈                |
| ------ | ------------------- | ------------------- | ------------------- | ------------------- |
| S      | 63.7 / 65.3（−1.6） | 47.1 / 48.5（−1.4） | 44.4 / 44.0（+0.4） | 16.4 / 18.7（−2.3） |
| M      | 67.0 / 68.5（−1.5） | 48.8 / 51.0（−2.2） | 45.3 / 47.5（−2.2） | 18.7 / 19.5（−0.8） |
| L      | 72.8 / 73.5（−0.7） | 51.9 / 55.0（−3.1） | 48.0 / 49.0（−1.0） | 20.1 / 22.5（−2.4） |
| XL     | 77.6 / 77.0（+0.6） | 56.3 / 58.0（−1.7） | 55.5 / 54.0（+1.5） | 22.4 / 23.5（−1.1） |

| 寸法 | 誤差の平均（絶対値） | 誤差の最大 | 誤差率の最大 | 差の平均 |
| ---- | -------------------- | ---------- | ------------ | -------- |
| 着丈 | 1.1                  | 1.6        | 2.5%         | −0.8     |
| 身幅 | 2.1                  | 3.1        | 5.6%         | −2.1     |
| 肩幅 | 1.3                  | 2.2        | 4.6%         | −0.3     |
| 袖丈 | 1.7                  | 2.4        | 12.3%        | −1.7     |

- 誤差の平均は、どの寸法も2.1cm以内だった
- 身幅と袖丈は、4着ともアプリのほうが短かった。測り方のくせとみられるが、原因はまだ確かめていない
- 肩幅は、アプリのほうが長い服と短い服がまじり、くせは見えなかった
- 袖丈は長さが短いので、cmの誤差は小さくても、誤差率では大きい
- 誤差率は、1着ずつ「誤差（絶対値）÷メジャーの値」で求め、4着の中で一番大きいものを出した。そのため、誤差の最大と誤差率の最大は、別の服のことがある（袖丈は、誤差の最大2.4cmがL、誤差率の最大12.3%がSの2.3÷18.7）

まだTシャツだけで、同じ服を撮り直したときのばらつきも測っていない。長そでとズボンは、測ったら足す（#77）。3Dへ渡す寸法の定義による差（股下や長そでの袖丈など。#68）も、そのときに採寸の誤差と分けて書く。

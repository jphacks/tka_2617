# pitariの半袖トップス用UVテンプレート

服の前面・背面の写真を、`pitari.blend`の半袖トップスのUVテクスチャへ変換するためのスクリプトと、ローカルでの検証記録。2026-10-12作成。

**状態：テンプレートの作成と3Dモデル上の確認まで完了。写真からテクスチャを作る試行用のスクリプト（下の「写真で試す」）で、合成写真と、実際のTシャツの写真1組（商品写真のような平置き写真）を試した。背景の小物を服の領域から手で除く修正が1回必要だった。いろいろな服や撮り方での精度は未検証。** 実写で確認していない項目は最後の「未確認のこと」にまとめた。

## Blenderの操作について

- このセッションでは、Blender MCPのツールが読み込まれていなかった。プロジェクトの設定（`~/.claude.json`のこのプロジェクト）には`blender`サーバー（`uvx blender-mcp`）があり、Blender側のアドオンも`127.0.0.1:9876`で待ち受けていた。MCPを使うには、Claude Codeで`/mcp`を開いて`blender`が接続済みになっているか確認し、接続されていなければ再接続してからセッションを始め直す。
- 起動中のBlenderには、アドオンのソケットへ**読み取りだけ**の問い合わせを直接送った（MCPツール経由ではない）。`pitari.blend`が開かれ、未保存の変更があり、対象の服が編集モードだった。そのBlenderでは別ファイルを開かず、保存もしていない。
- 起動中のBlenderの対象の服は、面・頂点・UV（編集中のbmeshの値）・材質・シェイプキーの値がディスク上の`pitari.blend`と一致した。未保存の変更はこのテンプレートに影響しない。対象の服以外の未保存の変更は調べていない。
- 実際の作業は、ディスク上の`pitari.blend`のコピー（`pitari_uv_work.blend`）を、別プロセスのBlender 4.3.2でバックグラウンド実行して行った。こちらから`pitari.blend`へ書き込んだことはない。
- 作業中の14:50に、`pitari.blend`がBlender側で保存し直された（SHA-256が`a99b782d…`から`64081db0…`へ。旧版は`pitari.blend1`に残っている）。対象の服を編集モードのまま保存したもので、オブジェクトモードに戻すと3つのメッシュの面・頂点・UV・シェイプキー・頂点グループ・材質は旧版と同じだった。テンプレートは新しい版から作り直し、面とUVのハッシュ（`topology_sha256`）が変わらないことを確かめた。
- 編集モードのまま保存されたファイルは、そのまま読むとUVが空になる。スクリプトはどれも最初にオブジェクトモードへ戻す。

### 今の構成では対応できない箇所と、必要な変更

UVの再展開・メッシュの変更・モディファイアの適用はしていない。

1. **材質の共有**：トップス専用の材質を作って割り当てる必要がある。作業用.blendでは`pitari_uv_check`に替えて確認した。元の`pitari.blend`とアプリ用のGLBは未変更。
2. **前後の切れ目が階段状**：写真の滑らかな脇線・肩線と合わず、階段の歯の部分は写真の色が届かない（`needs_fill`）。前後の境目に色の差があると3D上でもギザギザに見える（`renders/sheet_check_parts.png`の側面・脇の下）。直すには、肩・袖山・袖下・脇を滑らかな辺のループに沿って切り直し、UVを再展開する。再展開したらテンプレートを作り直す。
3. **袖の伸び**：袖山と袖付けのまわりで縦横比2〜20の面がある（`check/stretch_anisotropy.png`）。写真を貼ると、この部分の柄が引き伸ばされる。直すには袖の再展開が必要。
4. **外部画像の欠落**：元の`pitari.blend`の時点で、参照先`data/clothes/male_casualsuit06/`はリポジトリにもこのPCの主な場所にもない。作業用.blendでは、元と同じ場所（リポジトリ直下の`data/clothes/…`）を指す相対パスに付け直した。画像をそこへ置けば両方のファイルで読める。確認用の画像は作業用.blendへ取り込み済み。

## 座標の約束

実装は`scripts/uv_pixels.py`。

- **BlenderのUV**：画像の左下の角が(0, 0)、右上の角が(1, 1)。uは右、vは上。
- **テクスチャのピクセル座標**：画像の左上の角が(0, 0)。xは右、yは下。画素(col, row)は`[col, col+1)×[row, row+1)`の正方形で、中心は`(col+0.5, row+0.5)`。
- **変換**：`x = u × 幅`、`y = (1 − v) × 高さ`。逆は`u = x / 幅`、`v = 1 − y / 高さ`。画素中心のUVは`((col+0.5)/幅, 1 − (row+0.5)/高さ)`。
- **マスクの規則**：画素の中心が面のUV多角形の内側か辺上にあれば、その画素は面に含まれる。
- **OpenCVと既存の推論の点**：整数が画素の中心とみなす。このテンプレートのピクセル座標へは+0.5する。
- **glTF**：`TEXCOORD_0`は`(u, 1 − v)`。GLBへ書き出すと頂点番号は変わるが、UV座標は保たれる。three.jsのGLTFLoaderは`texture.flipY = false`で読む。
- **bpyの`Image.pixels`**：下の行から並ぶ。PNGの`row`行目はbpyでは`高さ − 1 − row`行目。
- **写真の座標**：写真ごとのピクセル座標で、UVとは別物。写真の点は画像ID・画像サイズ・元画像からの変換（回転・縮小・切り抜き）とひも付ける（`uv_template.json`の`photo_input_spec`）。

テクスチャは2048×2048、sRGBのPNGを前提にした。縫い目（島の縁）では、色を島の外へ8px広げる（`masks/all_uv_pad8.png`）。広げないと、3D上で島の縁に背景色の暗い点が出た（`renders/sheet_check_parts_no_padding.png`）。

## DeepFashion2との対応

番号の根拠：

- DeepFashion2公式の[ランドマークの図](https://github.com/switchablenorms/DeepFashion2/blob/master/images/cls.jpg)（Short sleeve topは1〜25）。図は前から見た服で、1は後ろ襟ぐりの中心、2と6は襟ぐりと肩線の交点、3〜5は前襟ぐり（4が中心）、7と25は肩先、9・10と23・22は袖口の角、12と20は脇、15〜17は裾の角と中心。
- 既存の推論（`apps/inference/pitari/geometry.py`）は、カテゴリ内の番号を1始まりでそのまま返す。HRNet公式実装`lib/dataset/deepfashion2.py`の`flip_pairs`で、左右のペアが2↔6、3↔5、7↔25、8↔24…15↔17、中央の点が1・4・16であることを確認した。

UV側の固定点は、メッシュの穴（襟ぐり・裾・袖口）、前後の切れ目、袖付けの線が交わる位置から計算した。中心の点は正中面（x=0）との交点。縫い目上の点はUV座標が前後の島で2つあるため、島ごとにUV座標と面・面コーナー（または辺と内分比）を保存した。

DeepFashion2の点では袖付けが表せないため、`aux_armhole_mid_{right,left}_{front,back}`（袖付けの線の中点）を別名で定義した。既存のモデルは推定しない。写真に縫い目が写っていれば手で指定し、なければ肩先と脇の中点で代用する（推定扱い）。

## 写真から貼るときの接続関係

`uv_template.json`の`views.front`・`views.back`に、写真側でも同じものを作れる形で保存した。

1. **区間**（`segments`）：固定点の間を境界に沿って区切ったもの。写真側の作り方は`photo_method`で決まる。
   - `contour`：写真の服の輪郭（切り抜きマスクの外周）上で、2点の間をたどる。
   - `neckline_curve`：前面の前襟ぐりは輪郭に出ないため、2・3・4（または4・5・6）を通る曲線を使う。精度は低い。
   - `armhole_curve`：袖付け。テンプレートの袖付けの曲線を、両端が肩先と脇に重なるよう回転・拡大・平行移動して置く。最初は直線で結んでいたが、合成写真の検査で袖付けの中点が最大51pxずれ、その誤差が身頃の内部まで広がったため変えた。
2. **区間の中の点**：各区間を約3cmおきに区切った位置（`samples[].fraction`、3Dの長さの割合）。写真側も輪郭の長さの同じ割合の位置に置く。平置きの実写は布の実寸に比例するため3Dの割合を使う。`fraction_uv`（UV上の長さの割合）は、UV画像から作った合成写真の検査用。
3. **内部点**：部位の中の格子点。写真側の位置は、UV側の輪郭（`polygon`）から求めた平均値座標の重みを、写真側の輪郭の点に掛けて求める（`scripts/warp_support.py`の`mean_value_weights`）。
4. **三角形**（`parts.<部位>.triangles`）：点の名前の3つ組。UV側でDelaunay分割し、部位の外の三角形を除いた。写真側でも同じ3つ組を使い、別々に分割しない。

三角形は部位ごとに作り、別部位をまたがない。前身頃の輪郭は前襟ぐりに沿うので、首の穴をまたぐ三角形はない。検査では、輪郭の辺がすべて三角形の辺として残っていることと、三角形の面積の和が部位の多角形の面積と一致することを確かめた。写真側では、ピクセル座標（y下向き）で見た三角形の符号付き面積の符号が、UV側をピクセル座標へ変換したものと同じであることを確認してから貼る。

三角形が直接届かない範囲（階段の歯など）は、前面で0.8%、背面で0.6%（`masks/needs_fill_*.png`）。

### 写真で観測できない、または点が足りない領域

- 内側（裏面）、独立した襟、見返しは写真から取らない。モデルにも独立した面がない。
- 前面写真の首の開き（前襟ぐり2-3-4-5-6と後ろ襟ぐり2-1-6の間）は後身頃の内側なので前身頃へ貼らない。
- 袖付けは輪郭に出ないので推定になる。脇の下・袖下はしわや影で色が信頼しにくい。
- 前後の切れ目の階段の歯は、写真の色が届かず推定で補う。

## 塗り残しの検査

`masks/all_uv.png`を基準に、次の3つを別々の8bitマスク（255＝該当）で管理する設計にした（`uv_template.json`の`coverage_spec`）。

- `observed`：写真の服の領域内の画素から色を取れたテクセル
- `filled`：写真の色がなく、周囲から推定して補ったテクセル
- `uncovered`：`all_uv − observed − filled`

袖付けや前襟ぐりの曲線など、推定した点を含む三角形で貼った部分は`low_confidence`として別に持つ。テクスチャの色が白・黒かどうかでは判定しない。

## Claude CodeからBlenderを操作する（MCPの接続）

この作業ではBlender MCPのツールを使えず、Blenderはバックグラウンド実行（`blender.exe -b`）で操作した。Claude Codeから起動中のBlenderを直接操作するには次のようにする。

1. Blenderを起動し、作業したいファイルを開く。3Dビューで`N`キーを押してサイドバーを開き、`BlenderMCP`タブで接続を開始する（`127.0.0.1:9876`で待ち受ける）。アドオンが見当たらなければ`uvx mcp-for-blender install-addon`で入れ直す。
2. MCPサーバーの設定は、このプロジェクトに`blender`（`uvx blender-mcp`）として登録済み。パッケージは`mcp-for-blender`に改名されている（旧名のままでも動く）。新しい名前にするには、ターミナルで次を実行する。

   ```powershell
   claude mcp remove blender -s local
   claude mcp add blender -s local -- uvx mcp-for-blender
   ```

   `claude`コマンドが使えなければ、この手順は飛ばしてよい（旧名のままでも動く）。

3. Claude Codeで`/mcp`を開き、`blender`が接続済みか確認する。失敗していれば再接続する。直らなければVS Codeのウィンドウを再読み込みし（コマンドパレットの「Developer: Reload Window」）、会話を開き直す。
4. 接続できたら、Claude Codeに「Blenderのシーンを確認して」などと頼むと、MCPのツールで起動中のBlenderを読み書きできる。

今回ツールが読み込まれなかったのは、`uvx blender-mcp`の初回のパッケージのダウンロード（約30パッケージ）に時間がかかり、セッションの開始時の接続が間に合わなかったためと考えられる（2026-10-12に単体で起動し、パッケージの取得とBlenderへの接続の試行まで動くことを確認した）。VS Codeを起動した後で`uv`を入れた場合は、PATHが古いままのこともあるので、VS Codeを再起動する。

MCPでつなぐと、Claude Codeが**起動中のBlenderの開いているファイル**を直接変更できる。保存していない作業があるときは先に保存し、元の`pitari.blend`ではなくコピーを開いて試すとよい。

## 確認できたこと

- 対象の服、UVマップ、材質、前後の島、袖付けの線を、Blenderの実際の面とUVから特定した。
- 6部位の面の対応表とマスクを作り、全面をちょうど1回ずつ覆うことを確認した。
- 前面のDeepFashion2番号と固定点の対応を、公式の図とHRNetの左右ペアに基づいて決めた。
- 固定点のUV座標と3D座標が一致することを、3Dモデル上で確認した。
- 部位ごとの三角形が輪郭に沿い、部位の外へ出ないこと。合成の変形（回転10°、縦横±10%、3%の波打ち）で裏返る三角形がないこと。
- 合成写真→テクスチャ→3Dモデルの流れが最後まで動き、反転や部位の取り違えなく貼れること（`trials/selftest/result_truth_uv/sheet.png`）。推論を使う経路も途中で止まらずに動くこと。
- 実際のTシャツの写真1組で、服の領域を1か所手で直せば、前後の柄が正しい向きで3Dモデルに貼れること（`trials/real1_fixed/sheet.png`）。

## 未確認のこと

- **いろいろな実写での精度**：試したのは商品写真のような1組だけ。スマホで撮った写真、しわ・影がある写真、A4を置いた写真、柄のない服などは試していない。
- **背面写真でのDeepFashion2の番号**：実写1枚では7番が画像の左に出たが、一般に成り立つかは未確認。1・3・4・5の位置も同様。
- **3・5・8・11・13・14・18・19・21・24の位置**：公式に位置の定義がなく、UV側は目安。
- **袖付け・前襟ぐりの写真側の推定精度**。
- **既存の推論の点の精度**：推論READMEのとおり、実写真での精度は未評価。
- **アプリのGLB**：`apps/web/public/models/tshirt.glb`と、このテンプレートのUVの一致は確かめていない。このスクリプトはアプリ用GLBを書き換えない。
- 起動中のBlenderの未保存の変更のうち、対象の服以外のもの。

## 実写のテクスチャ生成に必要な次の作業

1. 実際のTシャツで「写真で試す」の手順を通し、前後・左右・脇・襟まわりの見え方を確かめる。
2. 背面写真で、推論が7番を画像の左右どちらに出すかを確かめる。着用者の左袖に目印（テープなど）を付けると分かりやすい。
3. 推論の点を直す手間が大きければ、点の確認・修正の手段（画面または手順）を用意する。
4. アプリで使うなら、トップス専用の材質に分ける（パンツとの共有をやめる）。可能なら前後の切れ目を滑らかに切り直し、袖を再展開してからテンプレートを作り直す。
5. アプリの撮影画面の`cutout`は切り詰めた別の座標なので、テクスチャに使うなら切り抜き量を保存するか、`photo_to_texture.py`のように同じ座標のマスクを作る。
